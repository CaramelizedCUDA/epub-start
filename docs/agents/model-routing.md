# 模型与委派路由

模型身份以当前宿主实际提供的选择和可验证 model ID 为准，用户指定优先。模型自述、默认配置或 reasoning 等级不能改变模型身份；不同厂商的 `high`/`max` 也不等价。宿主不支持的模型或档位不能静默降级、替换 provider 或假设已经可用。

模型选择是任务路由建议，不是能力基准，也不扩大用户授权。先判断任务是否值得拆分；子任务边界清楚、交接成本合理并具有并行或独立审阅价值时，才可在当前授权范围内委派。委派可选，不创建用户侧新 task；主代理负责范围、证据审阅和最终交接。

用户偏好：凡选择 GPT-5.6 Luna，统一使用 `max`，包括主代理与子代理的调用，不因任务较小降低档位。是否委派、是否选择 Luna 仍按任务判断；用户后续明确指定优先。宿主不支持 `max` 时报告限制，不静默降档。Luna max 仍须执行结构化补充。

| 工作 | 精简候选 | 约束 |
| --- | --- | --- |
| 小范围查找、提取、清单核对 | Luna max | 只读，返回文件/行号与证据，不推导未给出的产品决策 |
| 较大范围代码阅读、关系追踪、资料归纳 | Terra medium；歧义增加时 high | 压缩返回证据，不把检索结果当实现验收 |
| 已明确契约的单模块实施与相关检查 | Sol high；小而清楚的窄实施可用 Luna max | 明确允许文件与检查；完成相关影响面验证后交回，不因型号降低项目门禁 |
| 高歧义设计、跨层竞态、契约演化、关键最终审阅 | Astra high/xhigh | 主代理自行处理或在授权范围内委派独立审阅，不为了并行切碎关键判断 |
| 未验证的外部模型 | 宿主实际支持并核实 model ID、工具与 reasoning 后再选 | 默认读取 [结构化执行补充](structured-execution.md)；未核实前不能作为自动可调用候选，也不能静默切换 provider |

Sol/Terra/Luna、其他非 Astra 或型号不明的执行者（无论是主代理还是子代理）必须读取 [结构化执行补充](structured-execution.md)。已确认的 GPT-6 Astra 可按任务自主选择精简方法，但同样遵守项目契约、同一验证矩阵和停止条件。模型切换后重新判断适用补充，不继承 Astra 的精简豁免；提高 reasoning 不能把非 Astra 视为 Astra。

每次派工至少交接：任务与完成标准、实际模型和推理等级、允许文件、相关契约章节、必跑检查、可复用证据、未授权动作、升级条件和返回格式。模型选择不能授予提交、推送、发布、安装依赖、发送外部消息或切换 provider 的权限。
