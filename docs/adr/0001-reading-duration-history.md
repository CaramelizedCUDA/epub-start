# ADR 0001：阅读时长、历史与推荐状态分离

- 日期：2026-08-28
- 状态：已接受
- 范围：B4 阅读洞察后端

## 背景

书架需要支持阅读时长、时间分布、继续阅读、阅读足迹和离线推荐。用户同时要求图书与历史可以独立管理：删书后可保留历史，删除历史也不得影响图书、进度或继续阅读。正文/精彩文段推荐未来仍有价值，但当前缺少稳定的选段、语言组织和防剧透规则。

## 决策

1. 产品统一称为“阅读时长”。只有 Reader 正文成功显示并且应用与页面前台可见时才累计；锁屏、切后台和离开 Reader 暂停。停在同一页仍计时，不设置空闲超时，Reader 界面不显示该数值。
2. 前台可见期间约每 30 秒确认一次。连续确认间隔最多接受 90 秒；更长间隔视为不可确认，不补算中间时间。进程被直接终止时只保留最后一次已确认时间，不向退出后外推。
3. 阅读历史与图书阅读状态是两个独立模块：
   - 阅读历史保存可删除的活动、可见区段和当时的书名、作者、系列快照；删书只移除实时关联，不删除历史。
   - 图书阅读状态只保存仍在书架中的首次/最近阅读时间；删除历史不触碰它，删书则随图书删除。
   - 阅读进度继续独立保存 CFI/progression，删除历史不触碰进度。
4. 历史只保存展示与聚合需要的快照，不保存来源路径、Android URI 或可重建正文。用户可以按活动、本地日期、历史图书身份或全部范围删除历史。
5. 继续阅读取最近阅读且仍在书架中的图书，并携带已保存进度。书架概览按日、周、月、季度返回中性的有序时间桶；阅读足迹按年或全部历史返回日单元，指标为阅读毫秒、图书数和系列数。图形布局由后续前端决定。
6. 首版离线推荐只返回三种结构化理由：系列下一本、较久未读完的图书、未开始的书架图书。推荐理由由前端本地化组织；后端不返回预先拼好的句子。
7. 正文、精彩文段和搜索索引不参与首版推荐。它们只登记为 Reader 完成后的正文推荐评审项；当前不增加空 Command、占位字段、永不产生的理由类型或通用 JSON 扩展口。

## 后果

- 同页停留会被计入阅读时长，这是明确的产品语义；该数值不宣称为精确专注时间。
- 直接杀进程最多少记一个正常确认周期，异常长间隔会保守少记而不会把后台时间误计入。
- 删书后的历史仍可显示当时的书名、作者和系列，但不能重新打开已删除图书；来源定位信息不会进入历史。
- 删除历史不会重置继续阅读或推荐状态；如用户要重置进度或书架状态，应使用各自独立操作。
- 未来正文推荐需要显式修改本 ADR、数据库/IPC 契约和测试，并重新评审：候选段落来源、章节与结局避让、语言生成模板、本地算法或模型、索引生命周期、隐私与失败回退。
