# 验证策略

本文件规定验证范围、升级条件和证据复用；[开发指南](DEVELOPMENT.md) 提供命令，[TODO](../TODO.md) 管理实现与阶段验收状态。适用于所有执行模型。历史验收记录保留当时范围与结论，不受新节奏追溯改写。

## 默认最小充分验证

验证范围由变更影响面决定，不由任务大小决定。先执行最相关的一层；只有失败、存在具体高风险传播路径或进入阶段门禁时才升级。不能用“更保险”“模型换了”“版本变了”作为重跑理由。

**除非能说明“本次改动可能通过什么机制破坏这个能力”，否则不得自行扩大验证范围。** 说明用一句具体因果关系即可，不要求每次编写风险报告。下表中的“必须”是底线，“建议”不影响本次完成状态。

| 影响面 | 必须执行 | 仅在触发时追加 |
| --- | --- | --- |
| 文档、注释 | 变更差异、相关链接、状态一致性 | 修改当前统计登记时核对统计；不构建应用 |
| 纯样式、普通按钮/面板展示 | 前端构建；受影响页面/布局的一次 UI smoke | 触摸、安全区、WebView 特有布局变化时在相应设备看该场景；不强制写状态测试 |
| store、异步协调、业务状态 | 前端构建；受影响的高价值行为测试 | 影响真实 IPC 消费时补该条集成路径；不把 mock 当真实持久化 |
| readerStore、engine、CFI、生命周期 | 前端构建；相关已有逻辑回归；实际 Reader 中被改变的打开/关闭、重排或恢复路径 | 平台差异涉及哪类就测哪类；共享生命周期变化至少 Windows 与一台 Android 相关路径，完整双机留阶段验收 |
| IPC、持久化、Rust、来源/缓存 | 契约同步；受影响 Rust 检查与测试；前端消费者变更时构建并验证消费路径 | 事务/错误映射/清理或租约语义变化才重测对应异常；SAF 权限链变化必须 Android 真机相关场景 |
| 依赖、打包、资源或原生配置 | 受影响目标构建和对应制品检查 | 包体/ABI/工具链等变化时 Android release 审计；签名/发布时按 E11 |

UI smoke 指实际打开受影响界面，执行改变的动作并确认结果；不是一张启动图。纯展示可以浏览器完成；Tauri、SQLite、SAF 和 EPUB.js 真实 DOM 行为须在对应运行环境验证。环境缺失时记录该项待验/阻塞，不能用自动测试替代结论；不受其影响的实现可以继续。

建议项：无传播路径的其他页面巡视、额外设备、额外随机样本、全量测试。日常提交和普通 PR 合并不自动触发这些项。必跑项全部通过、缺陷注入已清除且没有未解决的相关失败，即停止；不为填满表格继续截图、抓日志、重建或重跑。

## 实现与阶段门禁分开

E1–E9 的实现复选框只表示功能实现及本次影响面必跑检查完成；各平台尚未覆盖场景进入阶段清单。不能仅凭改规则给已有条目补勾，也不因延后的无关设备矩阵反复处理同一实现项。

| 节点 | 必须验收的范围 | 不自动要求 |
| --- | --- | --- |
| E1 集成检查 | 书架空/加载/失败重试、导航返回；相关并发逻辑；Windows 主流程与 Android 主流程证据，可复用有效记录 | SAF 撤权和底层存储压力；双机重复全部错误状态 |
| E2 集成检查 | 导入取消/失败、删除刷新与数据保留/级联、来源重新定位和重启；Windows 相关链路与一台 Android 的 SAF 失效/恢复 | 重跑未变化的 ENOSPC、SQLite FULL 或全样本矩阵 |
| E5 集成检查 | Reader 快速切换隔离、翻页/重排锚定、退出保存与重启恢复；Windows 与一台 Android 相关链路 | 无改动的系列/标签全流程与 APK 预算 |
| E10 跨端候选 | 同一源码候选的 Windows、Linux、旧 Android 与主流 Android；E1–E9 功能路径、兼容布局、代表样本、内存/性能/耗电；集中结清未测清单 | 已有后端压力证据未失效时重新做破坏性实验 |
| E11 正式签发 | 最终签名制品的预算、lint、版本/hash、签名及发布资料；Windows/Android 安装、启动、打开书与恢复的 smoke，其他发布平台对应 smoke | E10 后无功能变化时再做完整功能矩阵 |

E1/E2/E5 可以合并安排设备操作；延期须记录未测场景及承接节点，不阻塞无依赖的 E3–E9 实现。E10 集中验收完成才进入 E11 正式签发；可提前准备构建和签名流程。PR 合并使用变更影响面的必跑项；若 PR 本身宣布阶段完成，则同时满足该阶段门禁。失败只阻塞依赖该能力的完成/发布，不扩散为全项目“Android 阻塞”。

## 高价值测试与证据复用

长期保留能防止真实故障的测试：旧请求覆盖新列表、删除后列表/数据残留、CFI 恢复、旧 Reader 回调污染新会话、SAF 权限失效恢复。普通按钮/面板、可逆低影响修改，不新增镜像实现的测试资产。列表 mock 测试不能证明数据库清理，CFI/SAF 也不能用伪造结果证明。

新增或改变测试断言/行为时，证明测试能发现目标故障：修复前真实缺陷复现变红后修复变绿即可；没有原始失败时，在隔离副本临时注入目标缺陷再恢复。记录注入点、失败断言和恢复结果，异常测试必须真的到达目标步骤。无需为每次重跑、纯测试排版或文档变更重新注入。禁止保留故意缺陷或为了通过测试放松产品约束。

复用证据记录一行：记录链接/版本、已覆盖行为、本次为何不影响、未覆盖范围。检查实现、契约、相关依赖、平台环境和制品配置是否改变；只使受影响部分失效，不因提交号不同使所有证据失效。来源/缓存/Rust 均未变化且没有新的相关失败时，复用已记录的 ENOSPC/SQLite FULL；普通前端开发不重建 APK 证明预算，最终制品仍需 E11 核对。不同设备、profile/release 不互称覆盖；同一源码的逻辑证据可以复用，签名/安装/体积证据须对应实际制品。

## 前端机械执行路径

自动入口、参数和输出见 [开发指南](DEVELOPMENT.md#前端回归)。当前自动化覆盖实际 libraryStore 的并发与加载行为，以及 readerStore 的开关书会话隔离；Reader 测试替换 EPUB.js 与 DOM 重排边界，不宣称 UI、真实 CFI、数据库或 SAF 已自动验收。后续修改相应能力时，才把适合自动化的高价值故障加入相同入口，不提前建立全套测试框架或新增依赖。

设备步骤按固定场景执行，在同阶段记录填 PASS / FAIL / NOT_RUN / BLOCKED；默认未执行，记录版本、设备、样本及实际结果，失败附最小日志即可。不要求连续截图或重复读库；只有判断目标结果需要时才采集。

| 场景 ID | 固定动作 | 通过条件 | 承接节点 |
| --- | --- | --- | --- |
| SHELF-01 | 空库启动 → 导入有效 EPUB → 打开正文 → 返回原入口 | 状态与实际结果一致，无卡加载或错误返回 | E1 |
| SHELF-02 | 不可读/无效来源导入 → 看到错误 → 恢复来源后同源重试 | 可恢复，无伪成功、重复项或旧结果覆盖 | E1/E2 |
| SOURCE-01 | 选择后取消；导入后撤销 SAF 授权，再重新定位并重启 | 取消无副作用；失效明确；恢复可读，保留契约要求的数据 | E2，Android |
| DELETE-01 | 含进度/批注的书触发删除，刷新并重启 | 列表与数据库按契约清理，其他书不受影响 | E2 |
| READER-01 | 快速开 A/关 A/开 B；在 B 翻页并返回 | 旧回调不污染 B，无重复实例或异常保存 | E5 |
| READER-02 | 在代表正文定位 → 改字号/窗口 → 退出重启 | 合理锚定同一内容，恢复实际保存位置 | E5 |
| CANDIDATE-01 | 按 TODO E3/E4/E6–E9 的功能清单逐项操作 | 写操作、重启恢复和交互符合对应契约；逐项列结果，不以整组启动代替 | E10 |

每次只选受影响场景或当前阶段场景。未选项无需逐行填表；阶段收尾集中列未测项。报告最小字段：任务/源码版本、影响机制、检查或场景 ID、命令/设备、结果、证据复用、未测与承接节点。主代理按影响面定范围，执行者完成相关检查，主代理审阅证据；不因模型切换重跑未失效的验证。
