# A+C 阅读足迹扩展：多方案静态探索

> **隔离设计草稿**：本目录只供人工比较，不属于生产前端，不修改 `src/`、Rust、SQLite、IPC 或 Tauri 配置。

## 目的

在既有 Editorial Personal Library（A+C）方向上，探索一个长期使用的 Library 首页：让读者先看到自己的阅读时长，再决定继续读哪一本，最后才查看离线生成的推荐。阅读足迹不塞进首页内容流，而是通过左侧导航进入独立页面，专门回看一年或更长时间的阅读经过。它不是统计 Dashboard，也不把阅读变成 streak、目标或成就系统。

页面的单一任务是：**从“我最近怎样读”自然地回到“我现在要读什么”。**

直接打开 [index.html](index.html) 可在“藏书”和“足迹”两页之间切换；藏书页可切换三种视觉方案与日/周/月/季度筛选，足迹页可切换某一年/总计范围。所有内容均为本地 mock 数据。

## 已冻结的产品边界

- “阅读时长”只出现在 Library 的足迹区域，不放进 Reader 正文或 Reader 控件条。
- 时长筛选固定为日、周、月、季度；足迹视图额外支持按年和“总计”。
- “继续阅读”只指向后端返回的 `continue_reading`，展示书籍、进度和上次阅读时间，不自行在 React 中猜测进度。
- “推荐阅读”只消费 `ReadingRecommendation` 的书籍和结构化 `reason`，由本地模板组织一句简短理由。
- 当前理由只覆盖系列下一本、较久未读完、书架中未开始三种情况；不读取正文、精彩段落、`search_documents` 或全文搜索索引，因此不处理选段质量、语言组织和剧透。
- 正文/精彩段落推荐是 Reader 完成后的独立评审项；本目录不增加 Command、字段或占位枚举。
- Desktop 的“藏书”页采用左侧阅读时长/继续阅读、右侧推荐；“足迹”作为左侧导航下的独立页面。Android 保持同一信息分组，在足迹页纵向呈现足迹内容，在藏书页纵向呈现：阅读时长 → 继续阅读 → 推荐。

## 与 B4 后端契约的映射

| 视觉区域 | 真实能力 | 本草稿的消费方式 |
| --- | --- | --- |
| 阅读时长 | `get_library_reading_overview` → `duration` | 用 `period` 切换日/周/月/季度，读取 `total_reading_ms` 与 `buckets` |
| 继续阅读 | `get_library_reading_overview` → `continue_reading` | `book`、`progress`、`last_read_at` 只读展示 |
| 离线推荐 | `get_library_reading_overview` → `recommendations` | `book` 与三种结构化 `reason` 本地化为一句话 |
| 年度/总计足迹 | `get_reading_footprint` → `scope` | `year` 显示自然日单元；`all` 显示跨年份总览 |

## 共同设计计划

### 视觉 token

这是 A+C 的冷静编辑感延伸，不采用常见的奶油底、霓虹绿 GitHub 克隆或整页圆角卡片：

| 角色 | 名称 | Hex |
| --- | --- | --- |
| 页面底 | Mineral paper | `#EDF1EE` |
| 主文字 | Wet ink | `#18272C` |
| 品牌线 | Spine teal | `#2E6E67` |
| 时间辅助 | Docket blue | `#5C7397` |
| 重点标记 | Brass tab | `#C5A76B` |
| 选择/浅层 | Quiet wash | `#D7E2DE` |

热力图使用离散色阶，不使用连续渐变；色阶表示 `reading_ms` 的区间，不表示好坏评价。

### 字体角色

- **UI**：`Segoe UI Variable` / `Noto Sans CJK SC` / `system-ui`，负责导航、按钮和长列表。
- **Reading**：`Iowan Old Style` / `Palatino Linotype` / `Noto Serif CJK SC`，只负责书名和阅读语境标题。
- **Utility**：`Bahnschrift SemiCondensed` / `Arial Narrow` / `system-ui`，只负责分钟、日期和小型统计数字。

### 唯一签名

整体只保留一个记忆点：**阅读时针**。它不是装饰性的圆环，而是把用户选择的日/周/月/季度时间粒度变成不同密度的阅读刻度；旁边永远有明确的分钟数，避免图形承担不可读的精度。

## 三个候选方向

### A — 轮盘档案 / Dial Folio

- 用一个不完整的圆形时间轮盘表达当前筛选周期；刻度来自 `duration.buckets`，中间只显示总时长。
- 轮盘下直接放“继续阅读”按钮和唯一的继续阅读书籍，保持“过去 → 下一本”的路径。
- 右侧推荐区像一张安静的 detail leaf，每条理由最多一行，系列理由优先显示系列名。
- **优点**：最准确地回应“时间轮盘”，功能辨识度最高。
- **风险**：容易看起来像数据分析面板；必须限制为一个主数字、一个轮盘和一个继续阅读对象。

### B — 书脊热图 / Spine Calendar

- 用自然日方格表达年/总计足迹；每个非零单元叠一条极细的书脊色线，表示当天接触过书，而不是模仿 GitHub 的绿色格子。
- 选中日期后只展开该日的分钟数、接触图书数和系列数；不显示 streak 或目标达成率。
- 推荐区使用与书脊线一致的窄色条，让足迹和书架产生关联。
- **优点**：最适合回看一年或全部历史，跨年份比较清楚。
- **风险**：热力图是熟悉的视觉语言，必须保留“书脊线 + 日历月份边界”的特征，避免变成通用贡献图。

### C — 季节书签 / Seasonal Ribbon

- 用一条横向阅读带串起季度、月份和重要阅读日；节点的高度表示时长，颜色表示接触图书/系列的丰富度。
- 日/周/月/季度筛选改变带的分段密度；年/总计足迹以同一条带折叠成多行。
- 推荐区像从阅读带旁抽出的三张书签，保留封面、书名和一句理由。
- **优点**：最有“个人阅读档案”气质，适合把时间视为回忆而不是成绩。
- **风险**：精确比较不如热图，移动端横向滚动需要辅助的列表语义。

### 初步建议

先把 **A 作为默认评审方向**，保留 B 作为年度/总计的稳健替代，C 作为更有情绪但仍克制的第三方案。三者共享同一 IPC 映射和书籍信息层级，差异只放在足迹图形，不让视觉方案反过来迫使后端增加字段。

## 推荐文案约束

前端只把结构化理由翻译成自然语言，不生成内容判断：

- `next_in_series`：说明“系列中的下一本”和前一本标题，避免暗示情节。
- `unfinished_return`：说明“已有一段时间没有读完”，不使用“拖延”“落后”等评价词。
- `unstarted_in_library`：说明“书架中尚未开始的一本”，不虚构题材或质量。

推荐卡片不展示正文摘录、精彩段落、搜索命中或任何可能剧透的内容。未来若重新评审正文推荐，必须在 Reader 完成后单独定义选段来源、结局避让、语言模板、隐私和失败回退。

## 评审顺序

1. 先在 10 本混合中/日/英书名上看信息密度和长标题换行。
2. 再用 100 本和长系列名验证继续阅读/推荐不会挤压主要内容。
3. 最后用 1000+ 本确认足迹、继续阅读和推荐仍是入口，而不是新的维护型 Dashboard。
4. 先裁决 A/B/C 的足迹表现，再决定是否进入 F1 生产壳层；本目录不等同于最终 `FRONTEND_DESIGN.md`。
