# Direction C — Personal Library / Reading Room

## 设计命题

这里的“Reading Room”是私人收藏的情绪，不是木头书架的拟物。Library 先回答“我最近与哪些书相处”，再提供最近加入、系列和完整藏书；Reader 只在需要时召回工具。

## 视觉选择

- 构图使用横向“阅读续接带”和开放式封面群组，不把每本书包进一层层圆角卡片。
- 绿色书布色 `#35695A` 只承担选择、进度和动作；暖色来自背景层次，不使用渐变、木纹或纸张纹理。
- UI 采用平台无衬线，书名和正文使用稳健衬线；CJK 不人为加字距，正文允许系统放大。
- Android 重新编排为纵向续读区、最近列表和底部导航，桌面横向结构没有被简单缩小。

## 代表屏

- Desktop Library：继续阅读带、系列开放群组、缺失封面和边界状态样本。
- Desktop Reader：安静态与控件态；目录/设置分别作为临时 sheet，不永久压缩正文。
- Android Library：触点至少 48px，续读与最近加入成为纵向主线。

## 状态与边界

页面中的进度、系列完成度和“昨天读过”仅是视觉 mock。若生产要以批量进度驱动它们，必须保留 `DESIGN_DEPENDENCY_REVIEW_REQUIRED`，不能用 N+1 IPC 或本地假状态实现。

本原型不提供导出入口，也不暗示统一全库搜索已经存在；来源失效、资源限制和索引状态使用现有错误/状态语义的文字示意。

## 自我批评

这条方向最容易滑向“温暖的媒体库首页”。因此刻意删掉了 streak、统计图、推荐算法、木纹和过多徽章；续接带只表达已有阅读关系，不表达新的业务事实。

## 评审问题

1. 1000+ 本时，续读带是否仍保持最多 3 个对象而不挤压真正的藏书浏览？
2. Android 底部导航是否需要系列入口，还是把系列留给临时筛选？
3. 长 CJK 系列名在开放群组中是否需要折叠或详情 leaf？
